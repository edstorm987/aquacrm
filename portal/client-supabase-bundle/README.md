# Aqua client-owned form intake — Supabase deployment bundle (v1)

This bundle is deployed into a **client's own Supabase project** (never Aqua's).
It is the secure replacement for the old browser-direct `POST /rest/v1/{table}`
export path. After deploying it and activating the connection in AquaCRM, an
exported static site submits forms **only** to the `aqua-form-submit` Edge
Function — the generated bytes contain no table endpoint, no anon/publishable
key, no service-role or webhook secret, and no caller-controlled destination.

## What it contains

- `migrations/0001_aqua_form_intake.sql` — the `aqua_intake` schema:
  - `form_configs` — the server-side map from a **public form id** to its fixed
    allowlisted fields, quotas, Turnstile secret, and the fail-closed
    `intake_enabled` switch (default **off**).
  - `link` — the per-site Aqua binding: the pointer-webhook URL and the two
    **separate** secrets (webhook vs. bounded read), plus `active` (default off).
  - `form_submissions` — where the Edge Function (service role) writes.
  - `rate_events`, `read_nonces` — rate-limit ledger and single-use read nonces.
  - **RLS is enabled and forced with no policies**, and every privilege is
    revoked from `anon`/`authenticated`/`public`. The public key can do
    **nothing** — no SELECT/INSERT/UPDATE/DELETE on any intake table.
- `functions/aqua-form-submit/` — the hardened intake Edge Function.
- `functions/aqua-form-read/` — the bounded, HMAC-authenticated server-to-server
  read (one row, allowlisted fields only) that Aqua uses instead of a SELECT.

## Security contract (what Prompt 04A verifies)

1. The anon/publishable key has **no** table SELECT/INSERT/UPDATE/DELETE.
2. `aqua-form-submit` enforces: fixed field allowlist + type/length/total-byte
   limits, unknown-field rejection, server-verified **Turnstile** + honeypot,
   per-site/IP **rate limiting** + quotas, **card-number (PAN/Luhn) rejection
   before any persistence or logging**, database-backed **idempotency**, generic
   public errors, no raw PII in logs, a server-side **form-id → destination**
   map, and origin allowlisting **as defence-in-depth only, never as auth**.
3. The service-role credential is read from the function's env and **never**
   leaves the runtime; it is never present in an export.
4. `aqua-form-read` requires a valid per-site **read** HMAC (distinct from the
   webhook secret), a fresh timestamp, and a **single-use nonce** (replay-safe),
   and returns only the form's allowlisted fields for exactly one row by id.
5. Aqua is notified with a **signed pointer** (the submission id), never the body.
6. Revoking the connection (Aqua deletes the vault record) and/or setting
   `link.active = false` or `form_configs.intake_enabled = false` makes
   already-deployed forms stop submitting — **fail-closed**.

## Deploy

```bash
# In the CLIENT'S project (their credentials, not Aqua's):
supabase db push                         # applies migrations/0001_aqua_form_intake.sql
supabase functions deploy aqua-form-submit
supabase functions deploy aqua-form-read
# Then seed aqua_intake.form_configs + aqua_intake.link (service role only),
# leaving intake_enabled/active OFF until the connection is tested and approved.
```

Required function env (set in the client project, never exported):
`SUPABASE_URL`, `SUPABASE_SERVICE_ROLE_KEY`, `AQUA_INTAKE_IP_SALT`.

### Retention (operational)

`aqua_intake.rate_events` and `aqua_intake.read_nonces` are append-only ledgers
that grow with traffic. Only rows inside the live windows matter — a `read_nonce`
is meaningless once older than the read function's ±5-minute skew bound, and a
`rate_event` once older than the largest configured `window_seconds`. Schedule a
periodic sweep (e.g. a `pg_cron` job) to delete rows past those windows, or the
tables grow unbounded. This is housekeeping, not a security control: replay and
rate-limit correctness hold regardless, because the functions only ever read
inside the live windows.

## Status

Browser-direct `/rest/v1/{table}` form submission is **removed**, not accepted or
deferred. This bundle is the only supported client-owned intake path. Activation
is gated on the acceptance checks in AquaCRM's pilot programme (Prompt 04A).
